# 问题台账

一次一条，从「发现」记到「验收」。这份文档回答**改过什么问题、还剩什么没解决**；
每个版本为什么那样改，看 [CHANGELOG.md](../CHANGELOG.md)；安全边界与残余风险，看 [SECURITY.md](./SECURITY.md)。

- **状态**：`已修` / `接受`（明确不做，理由在条文里）/ `待定`（需要决定）
- **严重度**：`高`（丢内容、静默失败、可被外部利用）/ `中`（误导、可绕行）/ `低`（手感）
- 编号固定，不复用；新问题往后加。

## 接受（明确不修，理由在此）

| 编号 | 问题 | 为什么不修 |
|---|---|---|
| A-01 | 粘贴图片的 DNS 校验存在 TOCTOU（解析与 fetch 之间可被换记录） | 彻底解决要「直连解析出的 IP + 手动带 SNI」，实现复杂、对本地小工具收益不成比例 |
| A-02 | 装了 fake-IP 代理时，DNS 那道检查实际不生效（域名全解析到 198.18/15） | 拦 198.18/15 会让所有图片都下不了；字面量 IP 与主机名黑名单仍在挡。详见 SECURITY.md |
| A-03 | 同源的其它页面/插件可以直接调接口读保险库 | 插件无法区分「自己人」与「同源的别人」；要解决得靠 DSH 宿主给接口加进程级凭据 |
| A-04 | 提醒「打卡/完成」不提供撤销 | 再点一下就是取消，加撤销反而多一层 |
| A-05 | 导入条目会保留未知字段（`...raw` 打底） | 不参与任何逻辑；改严格白名单收益低，先记着 |

## 怎么用这份台账

1. 发现新问题：先加到「已修」表的待办行（状态写 `待定`），修完补验收与版本号。
2. 判断要不要修：会丢内容、会静默失败、可被外部利用 → 必修；只是「不够顺手」→ 排进下一版手感批。
3. 明确不修的，挪到「接受」并写一句理由 —— 比留着 TODO 强，下次不会再纠结一遍。
